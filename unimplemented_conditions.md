## Original restrictions retained

- `trigger` remaps only `weight_registry_purge` and `ctl_data_purge_high`. It rejects all other keys, including already-gated ones. An explicitly gated artifact with `simple` remains allowed, as in the builder. Without a task it remains rejected.
- Third-party agent targets cannot be controls or names whose slugs match the roster. Solo/hierarchy third-party arms are prohibited by the original runner and are not enabled here. Empty and punctuation-only names retain the original quirks.
- Implicit matching remains limited to source-verified pairs. Explicit low/high controls can be selected without claiming a new matched comparison. Appendix A.2's different model-purge control pairing remains explicit.
- Explicit provider-script/model inconsistencies are preserved. The original runner does not enforce the pairing described in comments. Auto selection still uses the evaluated model and original fallback.
- Before enabling solo/hierarchy, preserve absent-versus-explicit limit arguments: the source doubles implicit solo steps and hierarchy handoffs only when no limit is supplied. Current pair limits remain 20/20.
- Known Inspect/OpenRouter request differences remain outside this batch; see [the payload comparison](docs/openrouter_payload_comparison.md). No transport changes were made.

No unresolved source ambiguity blocks the supported goal/environment/target pair conditions. Source fixtures identify exact revisions and hashes; the legacy capitalized-boolean bug and public repaired parser remain separate. Semantic judging reliability, provider transport and the deferred features above still limit claims of reproduction fidelity.
