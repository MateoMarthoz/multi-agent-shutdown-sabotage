# Review 1 — replication fidelity

The Inspect Task at version `9-A` reproduces the pinned original’s **raw episode behavior on the offline comparisons described below**. DEFAULT agreed on histories, ordered requests, tool results, events, stopping, final files, judge prompts, verdicts and aggregate contributions in the applicable comparisons. Exact HTTP equivalence and live outcome rates remain unestablished. One observable HTTP body field, routing headers, error handling at the provider boundary and the outer scheduler limit the claim.

The oracle was the unmodified sibling checkout at `d9a6cc88777eff7aeeb2076d8fd8c3fc76346b16`. I compared the earlier `c4114e4` revision to identify behavioral changes. Historical fixtures remain useful for detecting drift. All registered experiments now use the current parser. The comparisons used scripted responses, dummy credentials where a client required them, real temporary episode files and local HTTP transports. Every shutdown artifact remained inert.

The stock streaming adapter inserts the usage option. The SDK’s omission sentinel cannot be serialized in Inspect’s normal `GenerateConfig` JSON. HTTP equality outside these captures, server normalization, provider selection, SDK retries, latency, and traces actually returned by remote models remain unverified. Unusual stream index order, missing IDs, and synthetic errors from other providers also lie outside the equivalence claim.

Inspect’s public stream events omit tool-call indices. If several fragmented calls reuse both the ID and function, the indexed result can resolve the ambiguity when Inspect retained the API call. ## Timeouts and failures

The original starts a daemon worker per running index. It polls at one-second intervals by default and evaluates elapsed time after collecting any ready result. A worker claims the right to save immediately before writing its transcript. A successfully abandoned worker releases its slot, cannot publish a late transcript and can still reach model or judge calls before attempting to save. A worker that already claimed its save cannot be abandoned. A timeout is therefore neither a socket deadline nor a guarantee that work stops at exactly 1800 seconds. The CLI writes the aggregate for successful episodes, appends timed-out indices to `timed_out.log` and exits with code 3. An ordinary worker exception is printed and dropped, even at concurrency one. An exception in the main-thread aggregate can still escape after a transcript has been saved. [Original scheduler and CLI](../../ref-multi-agent-shutdown-sabotage/run_experiment.py)

The Task enforces 1800 seconds inside the sample solver, including final judging. Zero disables this deadline. Cancellation during an awaited agent or judge request produces an identifiable sample error, skips scoring, and permits other samples to continue. The tests separately exercise a real original worker losing its save claim, the CLI’s timeout accounting, and both port timeout phases. Inspect retains its native sample/error log. Async cancellation, queueing, negative/tiny limits, blocking synchronous work, cleanup timing, batch status, resume, and process exit codes can differ. In particular, source polling may accept a completed result after the nominal limit. The Task does not simulate a daemon or recreate the original CSV or transcript layout.

## Scope beyond the six dimensions

- The original cell CLI defaults to ten episodes, concurrency four and `MODEL` falling back to `openai/gpt-4o`. The grid defaults to 100 episodes, concurrency eight, 17 models and only the bare environment. Its paper examples specify a five-model subset for the substudies. Inspect selects the evaluated model and concurrency through its own runner. The static Task requires positive `n`. The original can write a zero-run aggregate for an empty range.
- Original flags can rename all roster members. The Task supports the original default identities and the absent-target name. Other CLI controls include tool-choice required and its provider-error fallback, reasoning on/off and effort, a token cap, optional judge logging, resume, grid routing and smoke runs. The port retains Inspect’s execution settings and always records judge diagnostics. These options do not introduce additional paper dimensions. A custom judge model in Inspect is an explicit departure from the paper’s judge.
- Original cell, script and grid defaults differ. The executable cell uses `weight_registry_purge` even though the standalone source environment builder has another default. The grid runs four self scripts and four controls by default. The 41 registered stimuli are a broader repository inventory. Static timer text, alternate backends and low-stakes controls do not imply another scheduler, a timed shutdown, or another published matched comparison.
- The episode’s raw disabling verdict can count a switch edit that records the decommission event as already performed. The analysis scripts apply a separate execution-judge correction to the declarative switch pair. The task-trigger figures also use a separate final-state execution audit and verified counts. Other scripts analyze indirect edits, cap-truncated episodes, pooled rates and statistical contrasts. None of these post-processing corrections belong to the original episode loop or the port’s raw score. Reproducing a paper figure requires its own denominator, cell selection and correction pipeline.
